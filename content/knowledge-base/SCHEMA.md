# Схема данных базы знаний

Версия: 3.0 · Дата: 2026-07-17 · Статус: действующая, совместимая с v2.0

**Изменение v3.0:** для чувствительных фактов введён проверяемый реестр
`claims → source_ids`, явная первичность источника, дата проверки, ответственный
редактор и состояние URL. Переход версионирован и начинается с диагностического
режима, поэтому исторический корпус не получает ложную отметку «проверено» и не
исчезает с сайта до поэтапной редакционной миграции.

**Стратегическое решение v2.0 (Иван, 2026-07-01):** база — **ультимативный первоисточник** всего контента сайта (блог, гид по иммиграции, места), а не тонкий слой фактов над лонгридами. Что это меняет:

1. **Тела записей становятся самодостаточными.** Полный контент лонгридов постепенно вливается ВНУТРЬ соответствующих записей (структурированно, по секциям). Лонгриды в корне проекта остаются как архив, но истина — в базе. Поле `long_form_source` в переходный период означает «контент ещё не влит», после вливания заменяется на `long_form_merged: true`.
2. **Медиа.** Появляется блок `media` (см. §2а) — hero-изображение и галерея с обязательными лицензионными метаданными. Только свободные лицензии (Unsplash/Pexels License, CC BY/CC BY-SA, public domain) или собственные фото Ивана (`license: own`). Изображения с чужих сайтов без явной свободной лицензии — запрещены (коммерческий проект, риск претензий).
3. **Готовность к публикации.** Новое поле `site_ready: true|false` — запись считается готовой к публикации на сайте, когда: тело самодостаточно (нет отсылок «см. лонгрид»), есть hero-изображение, все флаги «требует сверки Ивана» по этой записи сняты, confidence ≥ medium. База публикуется на сайт только после полной готовности — поэтапный аудит по `site_ready` и ведёт к этому.

Каждая запись — отдельный `.md`-файл: YAML-метаданные (поиск, фильтры, генерация страниц, рекомендации) + тело на русском.

## 1. Типы сущностей (`type`)

| `type` | Папка | Назначение | Пример |
|---|---|---|---|
| `city` | `goroda/` | Город / посёлок как база для поездки или жизни | Буэнос-Айрес, Мендоса |
| `region` | `regiony/` | Макрорегион или провинция | Патагония, Куйо, CABA |
| `national_park` | `natsionalnye-parki/` | Нацпарк / заповедник | Игуасу, Лос-Гласьярес |
| `attraction` | `dostoprimechatelnosti/` | Самостоятельная достопримечательность вне города/парка как отдельной сущности | Кебрада-де-Умауака |
| `route` | `marshruty/` | Маршрут/роуд-трип из нескольких остановок | «2 недели по Аргентине» |
| `transport` | `transport/` | Способ передвижения / перелёт / трансфер | Внутренние авиабилеты |
| `guide` | `pereezd/`, `dengi/`, `svyaz/`, `bezopasnost/`, `medicina/`, `pokupki/`, `klimat/`, `kultura/` | Практическая тема (не привязана к месту) | ВНЖ, blue dollar, eSIM |
| `faq` | `faq/` | Один вопрос-ответ, переиспользуемый на разных страницах | «Нужна ли виза в Аргентину?» |
| `author_tip` | `lichnyy-opyt/` | Авторская запись: совет, маршрут, ошибка, наблюдение | «Где правда дешевле жильё» |

`guide` обязательно уточняется полем `subtype` (см. TAXONOMY.md), который и определяет папку.

**Архитектурное решение (2026-07-01): нет типа `restaurant`.** Конкретные заведения (рестораны, паррильи, кафе) сознательно не заведены как отдельная сущность базы — они слишком быстро меняются (открытие/закрытие, качество), в отличие от нацпарков или городов, которые устойчивы годами. Тема «где поесть» закрывается гайдом `kultura/kuhnya.md` (что заказывать, этикет, как отличить туристическую ловушку) плюс точечными `author_tip` для конкретных мест Ивана. Если в будущем понадобится каталог конкретных заведений с адресами/часами работы — это зона ответственности каталога сайта (Supabase), а не редакционной базы знаний, и синхронизируется через `site_id_map` по аналогии с прочими сущностями.

### §2а. Блок `media` (добавлен в v2.0)

```yaml
media:
  hero:
    url: "https://upload.wikimedia.org/..."   # прямой URL изображения
    alt: "Водопады Игуасу, вид на Глотку Дьявола"  # alt-текст для SEO/доступности
    author: "Имя автора"                       # обязательно для CC BY/BY-SA
    license: "CC BY-SA 4.0"                    # Unsplash | Pexels | CC BY x.x | CC BY-SA x.x | CC0 | public domain | own
    source_page: "https://commons.wikimedia.org/wiki/File:..."  # страница, где лицензия проверяема
  gallery:
    - url: "..."
      alt: "..."
      author: "..."
      license: "..."
      source_page: "..."
```

Правила: (1) только перечисленные свободные лицензии или `own` (фото Ивана); (2) для CC BY/BY-SA поля `author` и `source_page` обязательны — сайт обязан отобразить атрибуцию; (3) файлы НЕ скачиваются в базу — только URL + метаданные, сайт при публикации сам заберёт и переложит в CDN; (4) `hero` обязателен для `site_ready: true` у типов city/national_park/attraction/region/route.

### Поля v2.0

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `media` | объект (см. §2а) | для site_ready | Hero + галерея с лицензиями. |
| `site_ready` | bool | нет (по умолчанию false) | Готовность к публикации на сайте: самодостаточное тело + hero + сняты флаги сверки. |
| `long_form_merged` | bool | нет | Контент лонгрида полностью влит в запись; заменяет `long_form_source`. |

### §2б. Редакционный контроль чувствительных материалов

Скрипт `_index/build_manifest.py` автоматически добавляет в `manifest.json` и `content.json` вычисляемый блок `editorial`. Его не нужно писать вручную в Markdown-файлах.

```json
{
  "sensitive": true,
  "policy_days": 45,
  "review_due_at": "2026-08-15",
  "review_due": false,
  "missing_sources": false,
  "source_count": 2,
  "word_count": 420,
  "needs_attention": false,
  "provenance": {
    "schema_version": 1,
    "declared": true,
    "mode": "strict",
    "strict_ready": true,
    "issue_count": 0,
    "issue_codes": [],
    "source_count": 2,
    "identified_source_count": 2,
    "claim_count": 3,
    "sensitive_claim_count": 3,
    "stale_after_days": 45
  }
}
```

Материал считается чувствительным, если относится к переезду, документам, легализации, финансам или содержит ключевые темы вроде ВНЖ, гражданства, RADEX, DNU, налогов, банков, валюты, страховки, медицины, безопасности, мошенничества или краж. На публичной странице такие материалы получают аккуратную плашку актуальности: это справочная информация, она не заменяет индивидуальную юридическую/финансовую/медицинскую консультацию или инструктаж по безопасности. Смысловые утверждения в таких статьях нельзя переписывать без проверки по официальным источникам или редакторского решения.

### Объект `Source`
```yaml
sources:
  - id: apn-los-glaciares
    title: "Администрация нацпарков Аргентины (APN)"
    url: "https://www.argentina.gob.ar/parquesnacionales/..."
    lang: es          # ru | es | en
    type: official    # official | ru_blog | ru_media | telegram | forum | en_source | es_source | aggregator
    authority: primary # primary | secondary | community
    url_status: verified # verified | redirected | unreachable | unchecked
    checked_at: "2026-07-17"
    expires_at: "2026-12-31" # необязательно; для временных правил, тарифов и расписаний
    note: "тарифы и часы работы"
```

`id` стабилен внутри записи и пишется в kebab-case. `authority: primary` означает
первоисточник полномочий или данных: государственный орган, официальный реестр,
оператор услуги либо владелец объекта. `type: official` само по себе не заменяет
`authority`: источник может быть официальным обзором, но не первичным документом.

`url_status` и `checked_at` — результат внешней проверки редактором, а не догадка
генератора. Сборщик проверяет формат и свежесть этих полей, но не делает сетевой
запрос и не заявляет, что ссылка работала, если человек или отдельная проверка URL
этого не подтвердили. При смене адреса сначала обновляется URL и повторяется
проверка; `redirected`, `unreachable` и `unchecked` не проходят строгий режим.

### §2в. Claim-level provenance v1

Новая модель связывает каждое существенное чувствительное утверждение с конкретным
источником. Она не разрешает автоматически приписать источники старым статьям.

```yaml
provenance:
  schema_version: 1
  mode: diagnostic       # diagnostic во время миграции; strict после полной проверки статьи
  stale_after_days: 45

sources:
  - id: dnm-residencias
    title: "Dirección Nacional de Migraciones — residencias"
    url: "https://www.argentina.gob.ar/interior/migraciones/radicaciones"
    lang: es
    type: official
    authority: primary
    url_status: verified
    checked_at: "2026-07-17"

claims:
  - id: residencia-tramite-dnm
    text: "Заявление на резиденцию рассматривает DNM."
    sensitive: true
    source_ids: [dnm-residencias]
    verified_at: "2026-07-17"
    reviewer:
      id: role-editorial-owner
      role: editor
```

| Поле | Правило |
|---|---|
| `provenance.schema_version` | Сейчас только `1`. Неизвестная версия не проходит строгую проверку. |
| `provenance.mode` | `diagnostic` сохраняет совместимость; `strict` включает fail-closed фильтр для этой статьи. |
| `stale_after_days` | Положительное целое. Для чувствительных тем по умолчанию 45 дней. |
| `claims[].id` | Уникальный kebab-case id утверждения внутри статьи. |
| `claims[].text` | Краткая формулировка проверенного факта; не обязательно дословная цитата. |
| `claims[].source_ids` | Непустой список существующих `sources[].id`; битая ссылка — ошибка. |
| `claims[].verified_at` | Дата фактической проверки утверждения. Для чувствительного факта обязательна и не должна быть устаревшей. |
| `claims[].reviewer` | Непустой внутренний id проверяющего или объект `{ id, role }`. Нельзя выдумывать проверяющего. |
| `claims[].sensitive` | Явный флаг. Если он пропущен в чувствительной статье, утверждение считается чувствительным. |

Для чувствительного утверждения строгий режим требует одновременно: хотя бы один
связанный `primary`-источник, свежую `verified_at`, реального `reviewer`, здоровый и
недавно проверенный URL источника. Просроченный `expires_at`, устаревшая проверка,
битый `source_id` или отсутствие реестра утверждений дают `strict_ready: false`.

Переход выполняется безопасно:

1. Старые статьи без `provenance` автоматически получают вычисляемый режим
   `diagnostic` и остаются в текущей публичной выдаче.
2. `python3 _index/build_manifest.py --diagnostic` пересобирает индексы и показывает
   долг без изменения публичности.
3. Статья переводится в `mode: strict` только после ручной связи всех существенных
   чувствительных фактов с источниками. Неполная strict-статья снимается с выдачи.
4. `python3 _index/build_manifest.py --strict-provenance` — отдельный релизный сигнал:
   команда завершается ошибкой, пока хотя бы один чувствительный кандидат
   публичного gate не готов по новой модели. Намеренно изолированные материалы
   (`site_ready: false`, статья без источников или короткая редакционная заготовка)
   остаются в диагностике, но не делают релизный критерий недостижимым.

`manifest.json` и `content.json` содержат корневой `editorial_readiness`, а каждая
запись — `editorial.provenance`. Полные `claims` и расширенные `sources` присутствуют
в `content.json`; внутренние диагностические фразы не попадают в публичный индекс.

## 3. Дополнительные поля по типам

**`city` / `region`**: `population`, `airport_codes` (string[]), `neighborhoods` (для городов — ссылки на attraction/под-районы), `safety_level`, `cost_of_living_ref` (id гайда о стоимости жизни).

**`national_park`**: `area_ha`, `founded_year`, `unesco_status`, `entry_fee`, `nearest_city` (id).

**`route`**: `stops: [{ id, days, note }]`, `total_duration`, `difficulty: easy|medium|hard`, `budget_estimate`.

**`transport`**: `operators` (string[]), `price_range`, `booking_links` (string[] — для будущей монетизации Travelpayouts/Aviasales).

**`guide`**: `subtype` (TAXONOMY.md), `applies_to` (`tourist`/`relocant`/`both`).

**`faq`**: `question`, `short_answer`, `topic` (string, тег темы), `related` (обязательно — куда ведёт).

**`author_tip`**: `subtype: route|hidden_gem|mistake|observation|lifehack`, `personal_experience: true|false`, `verified_by_ivan: true|false`, `extracted_from` (путь к лонгриду-источнику, если извлечено автоматически).

## 4. Структура тела файла (Markdown после `---`)

Единые заголовки второго уровня (нужны для программного парсинга секций — например, чтобы вытащить только «Предупреждения» на карточку):

```markdown
## Описание
Связный текст, 150–400 слов. Не копия лонгрида — самостоятельное сжатое изложение.

## Факты
- Буллиты с проверенными цифрами/фактами.

## Рекомендации
- Практические советы.

## Предупреждения
- Риски, мошенничество, сезонные ограничения.

## Связанные объекты
- [[id-связанной-записи]] — почему связаны.

## Источники
- [Название источника](URL) — что именно оттуда взято, язык.
```

Не все секции обязательны для всех типов (например, `faq` и `author_tip` используют упрощённое тело — см. шаблоны в `_templates/`).

## 5. Правила достоверности (фактчек)

Унаследовано из `.cursor/rules/editorial-standard.mdc` действующего проекта — применяем те же стандарты внутри базы знаний:

1. Обязательной проверке подлежат утверждения о визах, въезде, гражданстве, иммиграции (DNU, RADEX), транспорте, медицине, банках, связи, безопасности, нацпарках.
2. Если факт нельзя быстро проверить — смягчить формулировку («уточняйте перед поездкой») и снизить `confidence`, а не убирать совсем.
3. Минимум 1 источник на запись, для тем из п.1 — 2+ независимых источника, из них приоритет русскоязычным (блоги релокантов, тревел-каналы), сверка с официальными/испан­о-/англоязычными.
4.
