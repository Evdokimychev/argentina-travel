# База знаний «Пора в Аргентину»

Единый структурированный источник фактов об Аргентине: для генерации страниц сайта, поиска, рекомендаций, маршрутов и FAQ. Не блог и не лонгриды — это слой **данных**, на основе которого позже своими словами пишется любой контент сайта.

## Зачем отдельно от уже написанных статей

В проекте уже есть ~38 готовых лонгридов (нацпарки, переезд, деньги, маршруты, города — корень папки проекта). Они отличные, но это **проза**: единый текст без полей, без координат, без машиночитаемых связей. База знаний — это извлечённые из них (и из новых источников) **структурированные факты**: каждая сущность — отдельный файл с метаданными + краткое тело. Лонгриды никуда не делись, остаются «развёрнутой версией» — на них стоит ссылка `long_form_source` в каждой связанной записи.

```
Источники (RU/ES/EN)  →  Лонгриды проекта (уже частично готовы)  ┐
                                                                   ├→  БАЗА ЗНАНИЙ (этот слой)  →  Сайт (Supabase / Cursor)
Новое исследование по пробелам  ───────────────────────────────┘
```

## Принципы наполнения

1. **Факты, не копии.** Изучаем источник, извлекаем проверяемый факт своими словами, сохраняем ссылку. Дословный объёмный копипаст — запрещён, короткие цитаты допустимы со ссылкой.
2. **Приоритет русскоязычных источников** (блоги релокантов, travel-каналы, форумы) — но обязательно сверяем с официальными/испан­оязычными при расхождениях.
3. **Каждый факт — с источником и датой проверки** (`last_verified`, `sources[]`).
4. **Связность.** Каждая запись стремится иметь хотя бы одну связь (`related`) — изолированных островков в базе быть не должно.
5. **Расширяемость без поломок.** Новые поля — через `SCHEMA.md`, новые теги/регионы — через `TAXONOMY.md`. Никогда не вводить значение «на лету» в одной записи.

## Как добавить новую запись

1. Открыть подходящий шаблон в `_templates/`.
2. Заполнить обязательные поля (см. `SCHEMA.md` §2–3).
3. Найти 1–3 источника (RU приоритет), сверить цифры.
4. Заполнить `related` — хотя бы 2 связи на уже существующие записи.
5. Сохранить как `<папка>/<id>.md`.
6. Пересобрать `_index/manifest.json` (скрипт сборки — см. `_index/README.md`).

## Связь с сайтом и Cursor

Сайт (`argentina-travel`, Next.js/Supabase/Prisma) уже имеет свой граф знаний (`src/data/knowledge-graph`, `src/data/places-enrichment.ts`, `src/data/places-seed.ts`) и каталог мест с полями `history/interestingFacts/howToGetThere/nearbyHighlights/faq`. Поля этой базы спроектированы как расширенный надмножество того же самого, чтобы перенос делался почти один-в-один: `summary→shortDescription`, тело «Описание»→`fullDescription`/`history`, `recommendations`+«Факты»→`interestingFacts`, `how_to_get_there`→`howToGetThere`, FAQ-записи с `related`, содержащим id места,→`faq[]` этого места. Когда дойдёт до интеграции — отдельный промпт для Cursor (по аналогии с `cursor-promty.md`) пройдётся по базе и просинхронизирует данные в Supabase, не трогая то, что уже корректно на проде.

## Источники

Полный реестр — `_istochniki/registry.md`. Принцип: 2+ независимых источника для чувствительных тем (визы, деньги, безопасность, медицина), русскоязычные — в приоритете, испан­о-/англоязычные и официальные — для перепроверки.
