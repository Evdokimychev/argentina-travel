## 2. Fixed: stale widget allowlist causing false "unknown widget" warnings

**Root cause.** `src/editorial/utilities/audit.ts` hard-coded a `KNOWN_WIDGETS` set with only
the original 3 widget keys (`season-matrix`, `tourism-infographic`, `tourism-timeline`).
Fifteen real, rendered widgets added later (`steak-cut-selector`, `steak-cut-diagram`,
`steak-doneness-phrases`, `steak-order-scenarios`, `steak-bill-explainer`, `tango-glossary`,
`tango-ronda-diagram`, `tango-phrasebook`, `trip-type-selector`, `layer-system`,
`packing-list`, `destination-packing-cards`, `summer-winter-comparison`,
`what-not-to-pack`, `carry-on-packing`) were never added to this list, so every article using
them (`argentinian-steak-guide`, `tango-beginners-guide`, `patagonia-packing-list`) was
flagged as referencing an "unknown widget" — even though
`src/components/travel/TravelWidgetRenderer.tsx` renders every one of them correctly in
production.

**Fix.** `TravelWidgetRenderer.tsx` now exports `TRAVEL_WIDGET_KEYS` (the actual
canonical list, derived from its own `TravelWidgetKey` union) and the editorial audit imports
it instead of maintaining a second, drifting copy. Editorial audit warnings dropped from
**24 → 9** (the remaining 9 are legitimate "long text without a visual block" /
"too many callouts" editorial suggestions, plus informational `legacy-slug` notices for
intentionally-noindexed programmatic pages — not defects).

**Separately verified via the pre-existing issue ledger**
(`docs/content-overhaul/issue-ledger.csv`, row `widgets:unknown-editorial-key`): the specific
concern that an *unknown* widget key would leak a raw `widget: {key}` string to real users is
already **not reproducible** in the current code — `TravelWidgetRenderer` returns `null` for
any unrecognized key, and `BlogWidgetBlock`/`BlogSectionBody` don't add a fallback string
either. This looks like it was already fixed in a later commit than the one that produced
that ledger row; no code change was needed for that specific finding, only for the stale
allowlist above.

Commit: `fix(content): derive editorial widget allowlist from TravelWidgetRenderer`.
Verified: `npx tsc --noEmit`, `eslint` on both files, `vitest run src/editorial src/components/travel …` (92 tests), full `audit:quick`.

## 5. What was deliberately *not* done, and why

- Did not run a full production build + live-server sitemap crawl (`CONTENT_OVERHAUL_BASE_URL`)
  in this pass — that needs a stable local/staging candidate and is explicitly called out in
  `docs/content-overhaul/README.md` as a separate step; the KB-level fixes above don't depend
  on it, and forcing a full build/boot cycle for every content edit would have cost far more
  time than the fact-checking itself for comparatively little additional signal (the existing
  `content:links --strict` already gives 0-broken-public-link evidence without it).
- Did not touch `docs/project-governance/*` (Sprints 1–6, Supabase/Vercel infra program) — out
  of scope for a content task, and actively marked as a separate ongoing program by its own
  governance rules.
- Did not blindly bump `checked_at`/`last_verified` dates on any source without independently
  re-fetching it this session. Every date change in the two commits above is backed by an
  actual `WebFetch`/`WebSearch` call recorded in this log.
- Did not delete or rewrite `content/knowledge-base/README.md`'s outdated "sync not started"
  claim — flagged here instead, since rewriting internal process docs wasn't the highest-value
  use of remaining time versus fixing more live user-facing content.
