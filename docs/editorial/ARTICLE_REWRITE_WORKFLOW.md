# Цикл переработки статей блога

Цель: быстро улучшать статьи по одной, не блокируя инфраструктурную работу (P0 recovery, админка, туры).

## Как устроена публикация сейчас

1. **Базовый каталог** — файлы в `src/data/blog*.ts` / `src/data/blog-manual-from-md/` / `src/data/blog-editorial/`.
2. **CMS-оверрайды** — опубликованные документы типа `blog` в админке  
   `/admin/content/documents` могут перекрывать файл по slug.
3. **Публичная страница** — `https://www.goargentina.ru/blog/<slug>`.

Для правок «как для читателя» предпочтителен путь:

- либо обновление исходного TS/MD-источника + публикация через PR;
- либо правка CMS-документа в админке с последующей публикацией ревизии.

Пока Data API Supabase деградирован, надёжнее править **файловый источник** и выкатывать через защищённый `main`.

## Роли

| Кто | Что делает |
|-----|------------|
| Вы | Открываете статью, фиксируете проблемы, отправляете в ChatGPT |
| ChatGPT | Готовит улучшенный текст и чек-лист правок |
| Cursor-агент (этот чат) | Вносит правки в код/CMS, проверяет, готовит PR |
| Другой агент | Не трогаем его ветку `fix/p0-*` и PR #15 без явной просьбы |

## Ваш цикл на одну статью

1. Откройте статью на production или localhost.
2. Скопируйте промпт из `CHATGPT_ARTICLE_REVIEW_PROMPT.md`.
3. Вставьте URL + ваши комментарии + (по желанию) текст страницы.
4. Получите от ChatGPT: список проблем, готовую статью, meta title/description.
5. Пришлите в Cursor сообщение по шаблону ниже.

### Шаблон задания для Cursor

```text
Переработай статью блога.

Slug: <slug>
URL: https://www.goargentina.ru/blog/<slug>

Проблемы (кратко):
- ...

Готовый текст от ChatGPT:
---
<title>
...
---

Требования:
- литературный русский, без SEO-спама;
- факты о визах/деньгах/правилах — только проверяемые или с оговоркой;
- сохранить рабочие внутренние ссылки на туры/регионы/гайд, если они уместны;
- не ломать slug и URL;
- не трогать ветку P0 / чужой WIP.
```

## Очередь

Список статей ведём в `REWRITE_QUEUE.md`. Статусы: `todo` → `in_review` → `ready_for_agent` → `in_pr` → `done`.

## Что не смешивать в одном PR

- Переработку статьи и P0 recovery инфраструктуры.
- Массовый рерайт 10+ статей без явного запроса.
- Правки админки/модулей «заодно», если задача только про текст статьи.
