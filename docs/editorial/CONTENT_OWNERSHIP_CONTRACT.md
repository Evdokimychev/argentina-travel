# Content Ownership Contract — Content OS 2.0

Дата контракта: 2026-08-17.  
Статус: canonical policy для Sprint 3+.

## Принцип

Одна сущность — одна фактическая истина.  
Одна публичная страница — один canonical owner.  
Всё остальное — adapters, projections или generated artifacts.

Не создаём parallel Content OS (content-v2 / editorial-next / cms2).

## Слои

### Layer A — Knowledge Entity (факты)

Canonical owner: `content/knowledge-base/**` (+ Schema v3 claims/sources).

Примеры: place, region, park, route, immigration/finance/transport concept, FAQ claim, verified media metadata.

Проекции: destination/place pages, map, search, related, breadcrumbs — **не** editable SSOT фактов.

### Layer B — Editorial Document (нарратив)

Canonical owner зависит от family:

| Family | Canonical owner (editable) | Runtime merge |
|--------|----------------------------|---------------|
| Blog article | Markdown / typed module under sync pipeline → file blog representation; CMS override only when `cmsBlogCutover` or published CMS document intentionally owns the slug | `resolveBlogPost` / `resolveBlogCatalog` |
| Guide / content page | `src/data` content pages + CMS guide/landing when cutover flags say so | guide/landing resolvers |
| Destination composition | KB entity + destination CMS document | destination resolver |
| Homepage / landings | CMS landing / site globals where configured | landing resolver + site globals |

Canonical public block schema: **`BlogBodyBlock`** (`src/types/blog-content-blocks.ts`).  
`BlogRichBlock` — legacy/source format; bridge via `src/editorial/adapters/blog-body.ts` (`adaptRichBlockToBody` / `adaptRichArticleToBlogSections`).  
Public render path for `richArticleId` posts: adapt → `BlogPostSectionView` / `BlogBodyBlock` (Rich renderer is compatibility UI for gallery/lede only).  
Page Builder / CMS body использует `BlogBodyBlock` (`PageBuilderBlock` alias).

### Layer C — Derived projections

Generated only — never hand-edit as truth:

- sitemap, search index, JSON-LD, navigation, cards/snippets;
- `content/knowledge-base/_index/manifest.json` (+ CSV snapshots with `generated_at`);
- sync outputs from `sync-rich-articles` / `sync-manual-posts` when marked generated;
- audit inventories under `docs/audit/**` and `var/ops/**`.

## Precedence (deterministic)

### Blog

1. If `cmsBlogCutover === true`: CMS cutover catalog (with safety fallback to file catalog if CMS incomplete).  
2. Else: file catalog (`src/data/blog.ts` assembly) **merged** with published CMS documents by slug (`mergeBlogCatalog` — CMS wins per slug when complete).  
3. Editorial polish: `EDITORIAL_OVERRIDES` / typed blocks — temporary compatibility; migrate into Layer B document then remove.  
4. `legacyManual*` maps in `src/data/blog.ts` — migrate/remove; not long-term SSOT.

Resolver: `src/lib/cms/blog-resolver.ts`.

### Knowledge Base

1. Entity markdown/json in `content/knowledge-base/**`.  
2. Manifest/index generated by `content/knowledge-base/_index/build_manifest.py`.  
3. `site_id_map` bridges KB id ↔ site place/destination — do not invent parallel IDs.  
4. Public gate uses `status`, `site_ready`, provenance — quarantine is not silent omission without reason codes.

## Forbidden

- Editing the same article independently in Markdown + TS + CMS + override without documented owner.
- Treating generated TS/JSON as a second editable truth.
- Publishing sensitive claims without source/provenance.
- Creating a third block ecosystem alongside Body + Rich.

## Sprint 3 migration direction

1. Document + enforce this contract (this file + `npm run content:quality`).  
2. Batch-migrate `legacyManual*` and inline blog corpus into Layer B documents.  
3. Collapse Rich→Body at publish boundary; deprecate Rich renderer when usage = 0.  
4. Generate KB/public inventory numbers — never hand-copy stale counts into docs.
