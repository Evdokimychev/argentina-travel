# Контент-завод: Telegram, Instagram и WhatsApp

## Что реализовано

Админ-модуль `/admin/marketing/content-factory` хранит общий замысел материала и отдельные версии для каналов, ставит публикации в очередь, запускает их по расписанию и показывает результат приёма публикации каналом. Редактор умеет выбирать проверенный материал CMS или одобренный кандидат Argentina Knowledge, кампанию, редакционный срок и медиа с подтверждёнными правами. Ключи каналов вводятся в панели и сохраняются в Supabase Vault; браузер получает только список уже настроенных типов ключей.

Серверные точки:

| Назначение | Адрес |
|---|---|
| Управление из админки | `/api/admin/content-factory` |
| Планировщик публикаций | `/api/cron/content-factory-publish` |
| Вебхук WhatsApp | `/api/webhooks/meta/whatsapp` |
| Вебхук Instagram | `/api/webhooks/meta/instagram` |

## Подготовка базы

Миграция `20260719174112_content_factory_control_plane.sql` создаёт закрытые таблицы, очередь и Vault RPC. Следующая миграция `20260719182515_content_factory_operating_system.sql` добавляет кампании, шаблоны, журнал AI-генерации, редакционные согласования и снимки аналитики. Обе подготовлены в репозитории, но должны применяться только в общем окне миграций после проверки текущей production-схемы.

После применения выполнить:

```bash
npm run supabase:verify
npm run rls-audit
```

## Telegram

1. Открыть [@BotFather](https://t.me/BotFather), создать бота и получить токен.
2. Добавить бота администратором Telegram-канала с правом публикации сообщений.
3. В панели открыть `Маркетинг и коммуникации → Контент-завод → Подключения`.
4. Указать `@username` публичного канала (или его числовой `chat_id`) и токен бота.
5. Нажать «Сохранить и проверить». Сервер вызовет `getMe`, но токен обратно в браузер не вернёт.

Публикация поддерживает текст, изображение и видео. Длинный текст автоматически делится по ограничению Telegram. Официальный справочник: [Telegram Bot API](https://core.telegram.org/bots/api).

## Instagram

1. Аккаунт Instagram должен быть профессиональным.
2. В [Meta for Developers](https://developers.facebook.com/apps/) создать приложение и подключить Instagram API.
3. Получить идентификатор профессионального аккаунта и токен с правом публикации контента.
4. Заполнить в панели `Instagram User ID`, токен и актуальную версию Graph API.
5. Для вебхука дополнительно сохранить секрет приложения и самостоятельно выбранный длинный проверочный токен.

Контейнер создаётся через `/{ig-user-id}/media`, затем публикуется через `/{ig-user-id}/media_publish`. Изображение или видео должно быть доступно Meta по публичному HTTPS-адресу; локальный файл и закрытая ссылка не подойдут. Поддержаны публикация ленты, короткое видео и история. Официальная коллекция примеров: [Instagram API by Meta](https://www.postman.com/meta/instagram/documentation/6yqw8pt/instagram-api).

Адрес обратного вызова для Meta:

```text
https://www.goargentina.ru/api/webhooks/meta/instagram
```

Подписку включать только после production deploy и успешной проверки URL.

## WhatsApp

1. В приложении Meta добавить WhatsApp Business Platform.
2. Выбрать бизнес-номер и скопировать `Phone Number ID`.
3. Создать постоянный серверный токен с минимально необходимыми правами.
4. В панели сохранить `Phone Number ID`, токен, секрет приложения и длинный проверочный токен вебхука.
5. В Meta указать адрес обратного вызова:

```text
https://www.goargentina.ru/api/webhooks/meta/whatsapp
```

6. Подписаться как минимум на события `messages`.

Входящие сообщения проверяются по `X-Hub-Signature-256`, удаляются повторы и создаётся диалог во входящем ящике. Свободный текст можно использовать только в разрешённом Meta окне ответа клиенту; маркетинговая отправка должна использовать утверждённый шаблон и согласие получателя. Сообщение считается окончательно доставленным только после статусного вебхука — HTTP-ответ отправки означает принятие Meta, а не прочтение человеком.

## Расписание

`vercel.json` запускает очередь каждые пять минут. Маршрут принимает только `Authorization: Bearer <CRON_SECRET>`. Конкурирующие запуски пытаются атомарно перевести задание из `pending/retry` в `processing`, поэтому проигравший запуск пропускает уже занятое задание.

После production deploy проверить вручную:

```bash
curl -H "Authorization: Bearer $CRON_SECRET" \
  https://www.goargentina.ru/api/cron/content-factory-publish
```

Не добавлять реальные токены в команды, логи, задачи или Git.

## Подготовка версий с AI

Кнопка «Подготовить версии с AI» использует серверный Responses API и строгую JSON-схему. Исходный материал и модель фиксируются в журнале генерации, а ключ никогда не передаётся браузеру.

Серверные переменные:

```text
OPENAI_API_KEY=...
OPENAI_CONTENT_FACTORY_MODEL=gpt-5.6-luna
```

Модель можно заменить без изменения кода. Если ключ отсутствует или API временно недоступен, система создаёт безопасные структурные черновики только из введённого замысла и явно сообщает, что факты требуют ручной проверки.

## Ограничения текущего среза

- Meta App Review, бизнес-верификация, утверждение шаблонов WhatsApp и выдача production-токенов выполняются во внешних кабинетах владельцем.
- Ответ из единого входящего ящика ещё не связан с карточкой лида/бронирования; сообщения уже сохраняются в отдельной омниканальной модели для следующего шага.
- Карусель Instagram и сбор внешней аналитики заложены в формат и модель данных, но адаптер публикации карусели ещё не включён.
- Кампании, шаблоны и внешние метрики получили защищённую модель данных; их полные рабочие экраны входят в следующий этап после объединённого production-релиза.
