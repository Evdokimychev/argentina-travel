# Редакционный процесс публикации

## 1. Задание

Редактор фиксирует пользовательский вопрос, тип материала, canonical-сущность, аудиторию, владельца и срок актуальности. Если тема уже существует, новое задание получает действие `LIGHT_EDIT`, `EXPAND` или `MERGE`, а не второй URL.

## 2. Сбор доказательств

Сначала собираются первичные источники, затем независимые поясняющие. Для каждого чувствительного факта указываются конкретная страница, дата проверки и ответственный. Медиа выбирается только после проверки автора, лицензии и страницы происхождения.

## 3. Черновик

Текст следует `content-template-spec.md`, географическому и терминологическому глоссариям. Черновик не содержит внутренних команд, названий полей, обещаний будущей функции и неподтверждённых цен.

## 4. Редакторская проверка

Проверяются короткий ответ, структура, русский язык, CTA, canonical, внутренние связи, мобильное чтение и отсутствие смыслового дубля. Машинно переведённый материал остаётся изолированным до человеческой переработки.

## 5. Фактчек и права

- Фактчекер связывает чувствительные утверждения с источниками.
- Юридический проверяющий смотрит регулируемые темы и коммерческие оговорки.
- Медиа-владелец подтверждает права; автоматический audit подтверждает metadata, но не юридическую действительность лицензии.

## 6. Автоматические gates

Минимум:

```bash
npm run audit:quick
npm run media:rights:check
CONTENT_OVERHAUL_BASE_URL=http://127.0.0.1:3112 npx tsx scripts/content-overhaul-inventory.ts
```

Затем выполняются строгий публичный редакционный crawl, проверка sitemap/canonical/redirect и целевой браузерный сценарий. Нулевой код команды не заменяет просмотр результата и контрольных чисел.

## 7. Выпуск

Публикуется только проверенная версия. Sitemap и поиск обновляются после content freeze. Для внешнего предложения перед кнопкой остаются фактический поставщик, место оплаты и правила поддержки.

## 8. После выпуска

Проверяются production URL, canonical, отображение медиа, поиск, 404, формы и аналитическое событие. При критической ошибке материал временно снимается или функция отключается; нельзя оставлять пользователю ложное обещание.

## Статусы

`draft` → `editorial_review` → `fact_check` → `legal_or_media_review` → `ready` → `published` → `scheduled_review`.

Любой этап может вернуть материал в `blocked` или `quarantined` с причиной, владельцем и следующим действием. Архивация разрешена только с решением о redirect/noindex и записью в соответствующем CSV.
