# Контентная готовность «Пора в Аргентину»

Актуальный рабочий пакет редакционного аудита на 20 июля 2026 года. Он отделяет то, что уже можно показывать пользователю, от сырого наследия и от данных, которые нельзя считать подтверждёнными.

## Текущий срез

- база знаний: **689 записей**, из них **71 проходит усиленный публикационный шлюз** и **618 изолированы**;
- редакционный долг по глубине: **369 опубликованных исходников** короче минимума своего формата;
- русская адаптация: **202 географических заголовка** и **226 анонсов** требуют ручной редакторской работы;
- граф исходного архива: **162 записи без входящей связи**; публичный интерфейс не строит ссылки на карантинные записи;
- журнал содержит отдельную строку на каждую проблему; у одной записи может быть несколько причин изоляции;
- публичные записи базы не содержат известных маркеров машинного перевода, внутренних заметок редакции или сломанных заголовков.

Это не означает, что база полностью переработана. Напротив, инвентарь доказывает масштаб оставшейся ручной работы. Неготовые, иноязычные, слишком короткие, неподтверждённые и неатрибутированные материалы остаются вне sitemap, поиска и публичных ссылок до редакторской доработки.

## Что является доказательством

| Артефакт | Что подтверждает |
| --- | --- |
| `content-inventory.csv` | один реестр базы знаний и публичных маршрутов |
| `content-route-matrix.csv` | локальные базовые маршруты; при подключённом crawl — URL актуального sitemap |
| `content-gap-map.csv` | агрегированные причины изоляции материалов |
| `content-quality-score.csv` | воспроизводимую оценку по фактическим правилам публикации |
| `content-action-plan.csv` | следующее действие и владелец для каждой записи базы |
| `issue-ledger.csv` | отдельную строку на каждую найденную проблему |
| `inventory-summary.json` | контрольные итоги генерации |
| `var/ops/public-editorial-audit.json` | последний завершённый обход; его дату и base URL нельзя переносить на новый релиз автоматически |

Значения `not_recorded`, `not_measured` и `review_required` намеренны: они показывают отсутствие доказательства, а не маскируют его догадкой.

## Как обновить инвентарь

Запустить production-версию сайта локально, затем:

```bash
CONTENT_OVERHAUL_BASE_URL=http://127.0.0.1:3112 npx tsx scripts/content-overhaul-inventory.ts
npx vitest run src/lib/content-overhaul-inventory.test.ts
```

Генератор читает текущий `content/knowledge-base/_index/content.json`, применяет реальный публикационный шлюз `src/lib/knowledge-base/publication-quality.ts` и сверяет маршруты с текущим `/sitemap.xml`. Он не изменяет статьи и продуктовый код.

## Правила использования

1. Публичным считается только URL, который прошёл действующий шлюз и присутствует в проверяемой публичной поверхности.
2. Статус `quarantined` означает «не публиковать», а не «удалить».
3. Чувствительный факт без официального источника остаётся `LEGAL_REVIEW`.
4. Иноязычный или автоматически переведённый текст остаётся `HUMAN_REVIEW`; автоматическое «улучшение» не заменяет редактора.
5. Медиа-права сверяются с отдельным аудитом `docs/audit/media-rights-readiness-2026-07-16.md`; этот пакет не перезаписывает его выводы.
6. Оплата, вход, аналитика и внешние сервисы описываются как эксплуатационные зависимости, но не подменяют редакционную готовность.

## Граница готовности к запуску

Публичный контентный слой проходит строгий текстовый gate: минимальная глубина зависит от формата, значимый материал требует источника, просроченная проверка блокирует публикацию, а личная история требует явного автора и подтверждения. Это безопасный кандидат для редакционного просмотра, но не доказательство завершения всей базы. До production обязателен отдельный staging, репетиция миграций и проверка рабочих кабинетов.
