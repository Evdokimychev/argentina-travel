# Передача между параллельными спринтами

Документ нужен, чтобы несколько агентов не перезаписывали результаты друг друга в общей рабочей копии.

## Владелец этого пакета

Контентный спринт владеет только:

- `docs/content-overhaul/**`;
- `scripts/content-overhaul-inventory.ts`;
- `src/lib/content-overhaul-inventory.test.ts`.

Он не меняет в этом этапе тексты базы знаний, бизнес-логику, дизайн-компоненты, интеграции, переменные окружения или структуру базы данных.

## Границы с соседними спринтами

| Соседний поток | Его территория | Как потребляем результат |
| --- | --- | --- |
| Медиа и права | `docs/audit/media-rights-readiness-2026-07-16.md` и связанные реестры | только читаем и переносим выводы со ссылкой на источник; исходный отчёт не редактируем |
| Главная и производительность | страницы, компоненты, сборка | повторно снимаем sitemap/публичный crawl после их завершения |
| Runtime и предупреждения | технические ошибки приложения | фиксируем только итоговый статус проверки, не меняем их код |
| Координатор релиза | общий приоритет и выпуск | передаём контрольные числа, блокеры и ручной чек-лист |

## Уже подтверждено

- Инвентарь построен на текущем sitemap из 625 URL.
- В базе 689 записей: 238 проходят публикационный шлюз, 451 остаётся изолированной.
- Строгий публичный редакционный аудит: 625 страниц, 0 ошибок.
- Публичные пустые состояния экскурсий не содержат команд разработчика и ведут к доступной альтернативе.
- `/blog/authors` является реальной публичной страницей, а не ошибочно распознанным slug статьи.

## Нельзя считать подтверждённым без чужого результата

- юридическое основание каждого изображения;
- владение production-доменом и внешними кабинетами;
- фактическая работоспособность оплаты, писем, OAuth и партнёрских API в production;
- item-level связь каждого утверждения с конкретным источником;
- качество 451 изолированной записи как будущей публикации.

Для таких строк используются `blocked` или `review_required`, указывается владелец и необходимое доказательство.

## Протокол перед финальной сборкой

1. Не отменять чужие изменения и не запускать массовое форматирование.
2. Перегенерировать инвентарь после стабилизации общей сборки.
3. Сверить медиа-реестры с отчётом медиа-спринта, не копируя неподтверждённые лицензии.
4. Повторить строгий публичный crawl и полный `npm run audit:quick`.
5. Передать координатору только фактические результаты и отдельный список действий владельца.
