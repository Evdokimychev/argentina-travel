# Контент-завод и центр каналов

## Назначение

Закрытый модуль админ-панели объединяет редакционную работу, распространение контента и входящие обращения. Это часть Argentina Travel, а не новый отдельный сервис. Ядро при этом не содержит аргентинских сущностей и сможет обслуживать будущие проекты через `project_key`.

## Единицы системы

| Сущность | Роль |
|---|---|
| `content_factory_items` | Общая идея, цель, аудитория, рубрика и связь с документом CMS |
| `content_factory_variants` | Отдельный текст и формат для каждого канала |
| `social_channel_connections` | Безопасное подключение аккаунта и несекретные настройки |
| `social_channel_secrets` | Ссылки на зашифрованные значения в Supabase Vault |
| `content_publication_jobs` | Надёжная очередь, повторы, внешний идентификатор и результат |
| `social_inbox_threads` | Диалог с человеком во внешнем канале |
| `social_inbox_messages` | Входящие и исходящие сообщения с защитой от повторных вебхуков |

## Поток контента

```text
Argentina Knowledge + CMS + идеи владельца
                    ↓
            общий материал
                    ↓
      Telegram / Instagram / WhatsApp
                    ↓
       проверка → очередь → адаптер API
                    ↓
        результат и ссылка в журнале
```

Планировщик забирает только наступившие задания. Каждое задание имеет ключ идемпотентности; конкурентные запуски не должны отправить материал дважды. Ошибка внешнего API сохраняется безопасным кодом без токена и допускает ограниченное число повторов.

## Подключения

- **Telegram:** бот, добавленный администратором канала; токен бота и `chat_id`/`@username`.
- **Instagram:** профессиональный аккаунт, приложение Meta, идентификатор аккаунта и токен с правом публикации. Медиа должно быть доступно Meta по публичному HTTPS-адресу.
- **WhatsApp:** WhatsApp Business Platform Cloud API, идентификатор номера, токен, секрет приложения и проверочный токен вебхука. Маркетинговые отправки выполняются только утверждёнными шаблонами и по согласившимся получателям.

Секреты вводятся в админке, передаются только на сервер и сохраняются в Vault. Ответы API никогда не возвращают секретные значения обратно в браузер.

## Входящие обращения

Meta отправляет подписанные вебхуки. Сервер проверяет `X-Hub-Signature-256`, удаляет повторы по внешнему идентификатору и сохраняет сообщения в отдельный омниканальный ящик. Поток можно связать с лидом или бронированием позднее без изменения внешних адаптеров.

## Редакционный контроль

Материал сайта продолжает проходить существующий `content_publication_gate`. Социальная версия не обходит проверку источников: если она связана с документом CMS повышенного риска, публикация разрешается только после готовности документа. Медиа использует существующую медиатеку и сведения о правах.

## Текущий операционный слой

Рабочий вертикальный срез включает подключение и проверку трёх каналов, создание вариантов, немедленную и запланированную публикацию, журнал приёма публикаций каналами и приём сообщений Meta. Операционное расширение добавляет кампании, шаблоны, согласования, снимки метрик и аудируемую AI-генерацию из проверенных материалов CMS и Argentina Knowledge. Статусные вебхуки доставки, полные рабочие экраны кампаний и расширенная внешняя аналитика подключаются следующим этапом без смены модели данных.
