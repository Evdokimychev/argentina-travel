# Источники данных интерактивной карты

Страница: `/mapa-argentina`. Сборка объектов: `src/lib/map-objects-server.ts` → `fetchMapObjects()`.

## Откуда берутся объекты

| Тип метки | Источник | Связанные страницы |
|---|---|---|
| Города, нацпарки, достопримечательности | `src/data/places-seed.ts` (или Prisma при `PLACES_USE_DB=true`) | `/places/[slug]`, подборки, маршруты |
| Опубликованные гео-статьи | `getAllEntries()` → `buildKbAttractionObjects()` | `/baza-znaniy/[id]` |
| Туры (`tour`) | `fetchMarketplaceTours()` | `/tours/[slug]` |
| Экскурсии (`excursion`) | `fetchExcursionsServer()`; координата города из Places | `/excursions/[slug]` |
| Все нацпарки локального геоснимка | `src/data/argentina-national-parks.ts` + `public/geo/map/national-parks.geojson` | Places/KB или официальный APN |
| Аэропорты | `src/data/argentina-airports.ts` | `/guide/kak-dobratsya` |
| Прямые рейсы между аэропортами | `src/data/argentina-flight-routes.ts` | дуги и карточка аэропорта → `/flights` |
| Транспортные узлы | `src/data/argentina-transport-hubs.ts` | places / destinations |
| Маршруты туров | `src/data/tour-routes.ts` | `/tours/[slug]` |
| Границы регионов | `src/data/argentina-regions.ts` | `/destinations/*` |

## Правила при добавлении мест

1. Новые города/достопримечательности добавлять в `PLACES_SEED` — так место автоматически
   получает страницу `/places/[slug]`, попадает на карту, в поиск и связи (relations).
2. `region` — строго из таксономии: «Центр и Пампа», «Патагония», «Северо-запад»,
   «Северо-восток», «Куйо», «Огненная Земля».
3. Факты (высоты, статусы ЮНЕСКО, сезоны) проверять; непроверяемое — смягчать
   («уточняйте перед поездкой»), см. `editorial-standard.mdc`.
4. Фото подключаются через `media-library/manifest.json` (`placeId` = slug места).
   Без фото карточка на карте показывает градиент по цвету категории — это нормально.
5. **Каждое место — только свои фото.** Заимствование обложек соседних мест запрещено.
   В `PLACE_COVER_FALLBACK_MAP` допустим только технический alias на прежний slug того же
   места; новые места без фото получают нейтральную графическую заглушку, а не логотип.
   Новые фото загружаются скриптом
   `scripts/fetch-place-media.mjs` (Wikimedia Commons, точечные запросы по месту);
   он же убирает дубликаты между местами.

## Прямые авиамаршруты

- Редакционный срез от `2026-07-19` покрывает все 40 аэропортов Аргентины с
  заявленными пассажирскими рейсами, включая Чапелько / Сан-Мартин-де-лос-Андес
  (`CPC`). Состав аэропортов сверяется отдельно от связей: иначе отсутствующая
  точка никогда не появится на карте даже при наличии маршрута.
- Канонический справочник карты — `ARGENTINA_FLIGHT_ROUTES` в
  `src/data/argentina-flight-routes.ts`. Он содержит только прямые маршруты между
  аэропортами, которые уже представлены на карте.
- Маршрут хранится один раз, но доступен в обоих направлениях через
  `getFlightConnections(iata)`.
- Для маршрута фиксируются тип обслуживания (`regular` или
  `seasonal_or_limited`), дата проверки, источник и — когда подтверждены —
  длительность, перевозчик и частотная пометка.
- Карта не выдаёт справочник за расписание на конкретный день. После выбора дуги
  пользователь переходит в `/flights`, где маршрут подставляется в действующий
  поиск авиабилетов.
- Источник нельзя обновлять из `Travelpayouts data/routes.json`: официальная
  документация отмечает, что этот файл больше не обновляется. До подключения
  лицензированного расписания справочник проверяется редакционно по открытым
  страницам расписаний и сайтам перевозчиков.
- При обновлении сети обязательно запускать
  `vitest run src/data/argentina-flight-routes.test.ts`: тест проверяет IATA-коды,
  отсутствие дубликатов, симметрию и покрытие всех аэропортов карты.

## Иерархия точек и сценарии

- Основные города и достопримечательности определяются по `popularity >= 80` либо
  редакционному `featured`; основные аэропорты задаются явным списком хабов.
- Второстепенные точки не удаляются: у них меньший пин, а подпись появляется только
  у основных объектов. `minZoom` реально применяется в MapLibre: локальные
  достопримечательности раскрываются при приближении, а выбранная точка остаётся
  видимой на любом масштабе. Полный набор доступен в сценарии «Все места».
- URL-параметр `focus` хранит туристический сценарий, `kind` — точный набор типов.
- «Что рядом» рассчитывается по координатам в радиусе 120 км. Без координат объект
  не показывается: это касается будущего каталога отелей и эстансий.

## Экскурсии на карте

- Используется объединённый опубликованный каталог platform + Tripster + Sputnik8.
- Если партнёр не отдаёт координаты встречи, экскурсия привязывается к найденному
  городу с небольшим детерминированным смещением, чтобы несколько карточек можно
  было открыть по отдельности.
- В карточке явно написано, что это городская привязка, а точное место встречи нужно
  проверять на странице экскурсии. Неизвестные города не получают выдуманных точек.
- Для многодневного тура без собственной координаты используется центральная точка
  его редакционного маршрута или найденный город назначения. Такая точка помечается
  как география программы, а не как точное место встречи.

## База знаний и полнота карты

- `getAllEntries()` уже применяет единый `publication-quality` gate: на карту
  допускаются только опубликованные материалы без заглушек, тонкого контента и
  проблем с обязательными источниками/медиа.
- Карта использует **все** прошедшие gate гео-материалы, а не только записи с
  доменом Argentina.travel. Дополнительная фильтрация по одному источнику раньше
  скрывала, например, готовую статью о Тигре.
- Сырые или короткие заготовки не выводятся ради искусственного количества.
  Отсутствующие важные места сначала оформляются как проверенный `Place` (например,
  Тревелин, Пилар, Сарате и кладбище Чакарита), затем получают полноценную статью.
- При недоступной БД карта через 1,5 секунды переходит на локальный каталог Places;
  это сохраняет точки и не оставляет пользователя перед бесконечной загрузкой.
- Не хардкодить новые факты в UI-компонентах: контент и provenance остаются в
  `src/data/*` или knowledge base, чтобы карта была только представлением данных.
